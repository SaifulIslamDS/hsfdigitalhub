# HSF Controlled Document Standard

**Document review:** Stable reference · **Last updated:** 20 October 2026 · **Planning & Compiled by:** Saiful Islam

Major HSF policies, frameworks, standards, SOPs, architecture baselines, MEAL frameworks, communication systems and brand standards should be treated as controlled records.

Where appropriate, a controlled document should identify:

- title;
- version;
- status (Draft / Candidate / Approved / Stable / Superseded / Archived);
- owner;
- approval authority;
- effective/review dates;
- classification;
- source/evidence basis where relevant;
- change summary;
- superseded version/reference.

## Stable baseline rule

Do not silently rewrite a stable historical baseline. Material changes require a controlled new version or an explicit unreleased/candidate state.

## Candidate rule

A candidate/repo-ready package is not a current policy merely because its files exist in the repository.

## Archive rule

Superseded and historical records should remain clearly identifiable and must not override current canonical documents.
