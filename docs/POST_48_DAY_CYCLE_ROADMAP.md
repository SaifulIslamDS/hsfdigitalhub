# HSF Roadmap After the First 48-Day Communication Cycle

**Purpose:** turn the first stable dual-stream cycle into evidence for the next controlled communication release.

## Phase 1 — Cycle closure (Days 49–52)

1. Freeze the completed v3.3 tracker.
2. Resolve blank publication links/status fields.
3. Record every morning substitution or skipped slot and reason.
4. Confirm evidence/consent status for published FIELD/EVENT/MOMENT content.
5. Record any safeguarding/privacy near miss or incident.
6. Archive final creative links where available.

**Output:** `Cycle_01_Completed_Tracker.xlsx` + short close note.

## Phase 2 — Communication MEAL review

Analyse three layers separately.

### Core P01–P48
- published / 48;
- Issue–Resolution pairs completed / 24;
- Special Engagement completed / 12;
- reach;
- meaningful engagement;
- shares;
- saves;
- useful comments/questions;
- performance by theme and format.

### HSF in Action
- FIELD / MOMENT / EVENT / OBS / HSF mix;
- planned vs actually published;
- substitutions/skips;
- strongest authentic-photo formats;
- repetition/saturation;
- evidence strength;
- safeguarding performance;
- staff production time.

### Programme representation
Review visibility across E4BL, A2PHC, Climate Action, Women/Girls/Rights, Humanitarian/Social Protection, Livelihood and Institutional/Volunteer/Partnership work.

Do not force equal quotas; interpret balance against actual programme activity.

## Phase 3 — Theme decisions

For each of the 24 themes, management selects:

- **Retain** — still relevant and performed well;
- **Refresh** — same theme, stronger angle/evidence needed;
- **Merge** — overlaps another theme;
- **Split** — topic proved too broad;
- **Retire** — no longer strategically useful.

Record the evidence behind each decision.

## Phase 4 — Activity communication learning

Compare the planned morning bank with what actually happened.

Identify:
- activities that consistently generated useful public documentation;
- programme areas with poor photo/evidence capture;
- recurrent activities that became repetitive on social media;
- activities better suited to Stories/albums rather than feed posts;
- activities that should be documented internally but not published publicly.

## Phase 5 — Governance and brand QA

1. Test representative Brand Design Stack v3.1.0 SVGs in Adobe Illustrator 2022.
2. Decide whether the production stack can become stable, needs a compatibility patch, or remains a candidate.
3. Review whether v2.3 dual-stream brand rules worked in real production.
4. Review platform-native behaviour on Facebook, Instagram and LinkedIn.

## Phase 6 — Cycle 2 design

Build the next cycle from:

**Cycle 1 evidence + current programme priorities + verified new evidence + audience questions + relevant observances + management priorities**

Do not automatically clone Cycle 1.

## Version decision

- Same architecture, refined content/operating rules → **Social Communication Plan v3.4**.
- Materially new architecture → consider **v4.0**.
- Knowledge Hub version should increment according to the scale of the approved institutional change.

## Longer-term ERP integration

Target workflow:

**Programme Activity → ERP Activity Record → Evidence/Media → MEAL Verification → Communication Approval → Public Communication → Performance/Learning**

Recommended future ERP communication fields:
- activity ID;
- programme;
- date/location;
- approved public summary;
- evidence link;
- media/consent status;
- public-claim classification;
- communication approval;
- published URL;
- performance summary;
- lesson/management action.

This will reduce manual reconstruction and strengthen HSF institutional memory.
