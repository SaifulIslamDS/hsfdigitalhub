# HSF Social Communication Overlay Register — Operating Guide

**Status:** Pilot guidance  
**Effective:** September 2026

The overlay register tracks `OBS / HSF / FIELD / EVENT / MOMENT` separately from P01–P48.

## ID convention

Use a separate sequence by category:

- `OBS-001`
- `HSF-001`
- `FIELD-001`
- `EVENT-001`
- `MOMENT-001`

Do not create P49, P50, etc.

## Required fields

The workbook includes fields for date/window, category, programme, location/context, related core theme, content/activity, format, evidence/source, evidence status, safeguarding/consent, approval, platform, publication status/link, performance and learning.

## Evidence status

Use one of:

- **Verified** — traceable to approved HSF record or authoritative source.
- **Observed / documented** — activity/media is documented but no broader outcome claim is implied.
- **Calculated** — derived from verified data with documented method.
- **Inferred / estimated** — should normally not be used for public field claims unless explicitly approved and labelled.
- **Pending verification** — do not publish the unsupported claim yet.

## Safeguarding / consent

Use the register to record whether publication checks are complete. A media file being available does not itself prove publication consent.

## Performance fields

Performance data should be interpreted by communication purpose. Use quantitative metrics together with qualitative learning. Reach alone is not evidence of communication quality.

## First pilot item

The register contains a starter record:

`FIELD-001 | 01 Sep 2026 | E4BL | Hazaribagh | Learning Material Distribution`

It is intentionally marked as requiring final safeguarding/consent and approval confirmation before publication status is treated as complete.
