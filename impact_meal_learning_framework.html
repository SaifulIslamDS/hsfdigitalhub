HSF Impact, Monitoring, Evaluation, Accountability & Learning Framework

A practical institutional framework for turning project activity and operational data into verified results, responsible public evidence, learning and better decisions.

01 · Impact, MEAL & Learning Framework

Purpose and Institutional Role

The framework should define how HSF understands, verifies and learns from project results. Operational data should become public impact evidence only after the meaning, scope, period and source have been checked.

Core principle: Evidence should support better decisions first; communication should use that evidence only after approval.
  • To establish one HSF-wide approach to monitoring, evaluation, accountability and learning.
  • To connect project delivery with indicators, evidence, learning and management decisions.
  • To make public statistics consistent across reports, proposals, website and social media.
  • To create a clear boundary between operational records and approved impact claims.
02 · Impact, MEAL & Learning Framework

MEAL Principles

Useful
Data should answer a real project or management question.
Proportionate
The evidence requirement should match the scale and risk of the project.
Traceable
Important figures should be linked to an identifiable source and reporting period.
Dignified
People should not be reduced to statistics, hardship or fundraising objects.
Inclusive
Relevant differences by age, sex, location or other approved categories should be visible where safe.
Learning-focused
Unexpected results and weaknesses should inform improvement rather than be hidden.

Results Chain

HSF project plans should distinguish what is invested, what is done, what is produced and what changes as a result.

Inputs → Activities → Outputs → Outcomes → Longer-term impact
LevelMeaningExample form
InputResources used.Staff time, budget, learning materials, medicines.
ActivityWork carried out.Class session, consultation, awareness session, training.
OutputDirect, countable result of an activity.Students attending, consultations completed, sessions delivered.
OutcomeMeaningful change in behaviour, access, knowledge, condition or performance.Improved progression, continuity, access or knowledge.
ImpactBroader or longer-term change to which HSF contributes.Should be claimed only when the evidence and method are appropriate.
05 · Impact, MEAL & Learning Framework

Theory of Change

Each major project should have a simple Theory of Change that explains why the selected activities are expected to contribute to desired outcomes.

Recommended logic: If HSF provides the planned support to the intended population, and key assumptions hold, then defined short- and medium-term outcomes are expected to improve.
  • Project need and affected population should be stated clearly.
  • The main barriers should be identified from available evidence.
  • HSF's contribution should be separated from changes caused by other actors or wider conditions.
  • Important assumptions and risks should be reviewed during project learning sessions.

08 · Impact, MEAL & Learning Framework

Baseline and Targets

Targets should be based on project capacity, available resources and a reasonable starting point rather than on attractive numbers.

  • A baseline should be recorded when an outcome indicator needs a starting reference.
  • Targets should have a time period and clear scope.
  • Targets may be revised when project conditions materially change, but the reason should be documented.
  • Absence of a valid baseline should be stated rather than replaced with an invented value.

10 · Impact, MEAL & Learning Framework

Data Quality Assurance

Important reporting should be checked through a simple data-quality process before analysis or publication.

Accuracy
The value should reflect the underlying record.
Completeness
Required records and fields should be present.
Consistency
The same definition should be used across periods and locations.
Timeliness
Data should represent the stated reporting period.
Uniqueness
Duplicate records should not inflate results.
Traceability
A reported figure should be traceable to its approved source.
11 · Impact, MEAL & Learning Framework

Disaggregation and Inclusion

Disaggregation should be used when it improves understanding and can be collected safely and responsibly.

  • Age, sex, location, project centre or other approved categories may be used when relevant.
  • Small groups should not be published when identification could become possible.
  • Categories should be defined consistently across data collection tools.
  • Disaggregation should support inclusion and better decisions rather than unnecessary profiling.

Monitoring Cycle

Monitoring should be built into normal project management rather than treated as a separate reporting exercise.

Collect → Validate → Review → Compare → Explain → Decide → Follow up
CycleTypical focus
MonthlyActivity, service, attendance, expenditure and immediate operational issues.
QuarterlyIndicator trends, targets, data quality, risk, feedback and corrective action.
Half-yearlyProgress toward outcomes, lessons, project adjustments and donor/internal reporting.
AnnualResults, learning, evidence quality, strategy and next-year priorities.
13 · Impact, MEAL & Learning Framework

Evaluation Standard

Evaluation should be used when a deeper assessment is needed than routine monitoring can provide.

  • The evaluation question, scope, method and intended use should be agreed before data collection.
  • Independent evaluation may be considered when donor requirements, scale, sensitivity or credibility needs justify it.
  • Limitations should be reported openly.
  • Findings should include practical recommendations and a management response where appropriate.
14 · Impact, MEAL & Learning Framework

Accountability and Community Feedback

People affected by HSF's work should have appropriate ways to share feedback, concerns and suggestions.

Listening
Feedback should be collected in a form appropriate to the project and community.
Response
Important concerns should receive a documented response or referral.
Learning
Recurring feedback should inform project improvement.
Protection
Sensitive feedback should be handled confidentially and safely.
15 · Impact, MEAL & Learning Framework

Complaints and Response

A complaint mechanism should be separate enough from general feedback to protect serious concerns and ensure follow-up.

  • Clear complaint channels should be available for relevant stakeholders.
  • Safeguarding, fraud, harassment, discrimination and other serious concerns should follow approved escalation pathways.
  • Complaint records should have access controls and retention rules.
  • Public reporting should use aggregate information only when appropriate and safe.
16 · Impact, MEAL & Learning Framework

Qualitative Evidence and Stories

Numbers should be complemented by qualitative evidence when a story, interview or observation helps explain what changed and why.

Context → Challenge → HSF response → Change → Evidence → Person's voice → Wider meaning → Consent
  • Stories should not be selected only because they are emotionally dramatic.
  • Consent and safeguarding should be confirmed before identifiable publication.
  • A composite story should never be presented as one real named person.
  • Qualitative findings should be distinguished from organization-wide statistical claims.
17 · Impact, MEAL & Learning Framework

Evidence Hierarchy and Public Claims

Not every database record should automatically become an impact claim. HSF should use a simple evidence hierarchy.

LevelEvidenceUse
1Operational recordAttendance, patient visit, activity, training or transaction record.
2Verified outputReviewed count or service result based on defined records.
3Outcome evidenceVerified change supported by an appropriate method.
4Impact evidenceLonger-term or broader change supported by suitable evidence and interpretation.
5Approved public claimEvidence cleared for website, social media, proposal, publication or donor reporting.
Public-claim rule: Stronger wording requires stronger evidence.
Connected use: Approved public claims may be adapted for social media under the Social Communication Plan and for the public website under the Website Content & Editorial Guidelines. Those documents should not redefine evidence levels.
18 · Impact, MEAL & Learning Framework

Current vs Cumulative Reporting

HSF statistics should clearly state whether a number describes the present period or the total reached over time.

TypeExample wording
Current“Active students as of [approved date/reporting period].”
Period total“Consultations recorded during [defined period].”
Cumulative“People reached since [defined start date], based on approved methodology.”

Different types should not be presented side by side without labels because they answer different questions.

19 · Impact, MEAL & Learning Framework

Learning and Adaptation

MEAL should help HSF understand what is working, what is not working and what should change.

Evidence → Reflection → Decision → Adjustment → Follow-up evidence
  • Quarterly or project-defined learning discussions should review trends, feedback, risks and unexpected results.
  • Lessons should be recorded in short, usable language.
  • Agreed actions should have an owner and follow-up date.
  • Positive results and weaknesses should both be used for organizational learning.

21 · Impact, MEAL & Learning Framework

ERP Integration

The ERP should support MEAL by capturing structured operational data, but the ERP should not decide automatically what counts as impact.

ERP record → Validation rule → Indicator calculation → Review → MEAL dashboard → Approved reporting dataset
  • Indicator definitions should be agreed before dashboard calculations are automated.
  • Source records should remain traceable from summary values where access permissions allow.
  • Public dashboards should use approved aggregate data only.
  • Patient, student, HR, payroll, safeguarding and other sensitive records should remain protected by role-based access.
22 · Impact, MEAL & Learning Framework

Dashboards and Data Visualization

Dashboards should help a manager answer a question quickly. They should not become collections of every available metric.

  • Each dashboard should have a defined audience and decision purpose.
  • Current period, previous period and target may be compared when the comparison is meaningful.
  • Charts should use clear labels, units and reporting periods.
  • Traffic-light status should be supported by visible text or labels, not color alone.
  • Public charts should avoid small-group disclosure and sensitive detail.
23 · Impact, MEAL & Learning Framework

Safeguarding, Privacy and Responsible Data

Evidence collection should never override dignity, privacy or safeguarding.

  • Only data required for a defined purpose should be collected.
  • Identifying details should be separated from analysis data when practical.
  • Children, patients and other people in sensitive contexts should receive stronger privacy protection.
  • Consent for a service should not automatically be treated as consent for public storytelling or photography.
  • Retention, access, export and deletion practices should follow approved HSF policies.
24 · Impact, MEAL & Learning Framework

Responsible AI-Assisted Analysis

AI may support analysis, summarization, coding of qualitative themes, draft visualization or reporting, but it should not become the source of HSF evidence.

  • Confidential or personally identifiable data should not be placed into an unapproved AI system.
  • AI-generated summaries should be checked against the source data.
  • AI should not invent missing values, quotations, outcomes or explanations.
  • Material decisions and public claims should remain under human review and approval.

26 · Impact, MEAL & Learning Framework

Review Calendar and Implementation

The framework should be introduced gradually so that project teams are not overloaded with unnecessary forms or indicators.

Phase 1 · Define
Project results chains, indicators, source records and reporting periods.
Phase 2 · Standardize
Forms, data dictionary, verification and reporting templates.
Phase 3 · Integrate
ERP fields, validation rules, dashboards and approval workflow.
Phase 4 · Learn
Quarterly review, evaluation, public evidence and continuous improvement.

Minimum institutional review rhythm

  • Monthly operational review should focus on delivery, completeness and immediate issues.
  • Quarterly MEAL review should focus on indicators, data quality, accountability and action.
  • Half-yearly review should examine outcome progress and project adaptation.
  • Annual review should summarize results, learning, evidence quality and priorities for the next cycle.
Implementation recommendation: A small number of reliable indicators should be preferred over a large number of weak indicators.
